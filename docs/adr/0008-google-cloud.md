# ADR 0008 — Spry on Google Cloud: which service for each piece

- Status: accepted (Lab 9)
- Date: 2026-11-14

## Context

Spry runs on AWS (Labs 2–7): a static Next.js export on S3 + CloudFront, the FastAPI
backend on Lambda behind a function URL, PostgreSQL on RDS `db.t4g.micro` (the AWS
Free plan does not allow Aurora, see Lab 2), the agenda parser on Lambda + Bedrock
(Nova Micro), infrastructure in CloudFormation and Terraform (HCP workspace `spry-dev`).
Spry has no sign-in, weekly report or queue yet (Labs 4–5 were not built), so those
rows have nothing to move today.

Lab 9 asks what the same system would take on Google Cloud. One constraint shaped
the result: the GCP Free Trial in Ukraine asks for a **$30 prepayment** before any
billable service (Cloud Run, Cloud SQL, Artifact Registry) can be used. Firebase
Hosting (Spark plan), BigQuery sandbox and Looker Studio need no billing account.

## Decision, row by row

| Spry on AWS | On Google Cloud | Decision | Why |
|---|---|---|---|
| S3 + CloudFront, static frontend | Firebase Hosting | **replace — deployed** | CDN + managed certificate included, free plan, no billing account needed. `firebase.json`, `make deploy-firebase`. |
| Lambda + function URL, FastAPI | Cloud Run | **replace — in Terraform, not applied** | Same container runs locally and in the cloud; the `runtime` stage of `backend/Dockerfile` has no Lambda layer, `entrypoint.sh` now listens on `$PORT`. Min instances 0, max 2, request-based billing. Blocked by the prepayment. |
| ECR | Artifact Registry | **replace — in Terraform** | Repository `spry`, cleanup policy keeps 3 images to stay inside 0.5 GB free. |
| RDS PostgreSQL `db.t4g.micro` | Cloud SQL for PostgreSQL `db-f1-micro`, 10 GB SSD | **replace, stopped when unused — in Terraform** | See *The database* below. |
| — (no DynamoDB) | Firestore | **rejected for now** | Would rewrite the data layer; see below. |
| — (no Cognito yet) | Identity Platform | **later** | Nothing to move. When sign-in comes: Identity Platform (50 000 MAU free vs Cognito's 10 000); the API would verify the ID token, and only then should Cloud Run stop allowing unauthenticated calls. |
| — (no EventBridge / SQS yet) | Cloud Scheduler, Pub/Sub or Cloud Tasks | **later** | The weekly report does not exist yet. Cloud Scheduler (3 jobs free) calling a Cloud Run endpoint is the plan; Cloud Tasks if it ever needs a work queue. |
| — (no SES yet) | no Google service | **keep SES** | See *E-mail*. |
| Bedrock (Nova Micro), agenda parser | Vertex AI (Gemini; Claude via Model Garden) | **keep on AWS** | It works, it is cheap, and the trial credit does not pay for partner models. Gemini Flash is the candidate if it moves. |
| Secrets Manager | Secret Manager | **replace — in Terraform** | The whole `DATABASE_URL` is one secret, generated by Terraform, read by the API's service account only. |
| CloudWatch Logs | Cloud Logging | **replace** | Automatic for Cloud Run stdout. |
| IAM roles | service accounts + IAM roles | **replace — in Terraform** | `spry-api` (Cloud SQL Client, Secret Accessor on one secret) and `terraform` (the six roles the lab lists, plus SA/IAM admin to create `spry-api`). No Owner/Editor, no default compute SA, **no JSON keys**: HCP Terraform reaches GCP through Workload Identity Federation (`gcp-bootstrap/`), the condition admits only workspace `spry-gcp` of org `ooad-yuliadovhai`. |
| Terraform `aws` provider, workspace `spry-dev` | Terraform `google` provider, workspace `spry-gcp` | **new workspace** | One plan cannot break both clouds. |

### The database

| Option | Latency | Bill (idle month) | Code |
|---|---|---|---|
| Cloud SQL around the clock | lowest (same region as Cloud Run) | ≈ $9.40 | none |
| **Cloud SQL stopped at night** (`make sql-stop`, later Cloud Scheduler) | same; first request after a start waits ~1 min | ≈ $1.70 (storage only) up to a few $ | none |
| Firestore | low | $0 | rewrite: meetings + agendas become documents, no joins, every list screen counted in reads |
| Keep RDS on AWS, call it across clouds | +~20–40 ms per query us-central1 ↔ us-east-1, several queries per request; RDS would need a public endpoint | AWS's ≈ $14 + egress | none, but security groups opened to the internet |

Chosen: **Cloud SQL, stopped outside use.** Spry's data is relational (an agenda belongs
to a meeting) and the migrations already exist; saving the last ~$2 a month is not worth
rewriting the data layer. Data load plan: run the Alembic migrations against the empty
database (the container does it on start) — the AWS data is test data.

What is deployed today, because of the prepayment: the frontend on Firebase calls the
API on AWS. That is the "keep the database on AWS" row in practice: it works, and it is
a migration state, not the target.

### E-mail

Keep **SES** (multicloud is allowed): it is already in the AWS account and is the
cheapest. If the report moves fully to GCP, the alternative is SendGrid or Mailgun;
its API key would live in **Secret Manager**, read only by the service account of the
report job.

### What we would not move

- **The agenda parser** — Bedrock works and the trial credit does not cover Claude on
  Vertex; moving it is a price/quality comparison for later, not a migration need.
- **The domain and DNS** (Namecheap → CloudFront) — Firebase Hosting can serve
  `app.yulia-spry.xyz` too, but switching the custom domain is the last step, once the
  API is on Cloud Run as well.

## Consequences

- The frontend runs on both clouds; the API and data remain on AWS until billing is enabled.
- `gcp/` describes the full target (Cloud Run + Cloud SQL + Artifact Registry + Secret
  Manager + service accounts); `terraform -chdir=gcp plan` shows it, `apply` needs billing.
- CORS on the AWS API must include `https://<project>.web.app`.
- The GCP database does not pause by itself — someone (or Cloud Scheduler) must stop it.
